# AGENTS.md — demo-file-service

Compact cheat-sheet for OpenCode sessions. Trust executable config; the full upgrade context is in `SPRING_BOOT_UPGRADE_PLAN.md`.

## Tech stack

- Java 25, Maven 3.9.9 (wrapper), Spring Boot 4.1.2, Spring Framework 7, Spring Cloud Azure 7.4.0.
- WebFlux (reactive), R2DBC MariaDB, Liquibase, Azure Blob Storage via Azurite, Resilience4j, MapStruct + Lombok.

## Build & test

- The Maven wrapper is **not executable** in this repo; run it via `bash`:
  - `bash ./mvnw clean verify` — full build + all tests.
  - `bash ./mvnw clean install -DskipTests` — build JAR only.
  - `bash ./mvnw test -Dtest=<ClassName>` — single/focused test class.
- Output JAR: `target/app.jar` (set by `<finalName>app</finalName>`).
- Tests require a working Docker daemon (Testcontainers spin up MariaDB and Azurite).
- The so-called integration tests (`FileServiceIntegrationTests`, `StorageRepositoryImplResilienseTest`, etc.) use the `*Tests.java` naming convention and therefore run in the Surefire `test` phase, not a separate Failsafe phase. Both `mvn test` and `mvn verify` run them.

## Local run

- `docker compose up` is the supported local run. It exposes the app at http://localhost:8081.
- The containerized app uses the `prod` profile via `docker/file-service.env`; MariaDB and Azurite are also started.
- `application-local.yml` exists for a localhost-only setup (port 8081, localhost MariaDB/Azurite), but note:
  - The Liquibase changelog only declares contexts `prod` and `test`. Running with the `local` profile will not apply the schema. Start with `prod` or set `spring.liquibase.contexts=prod` when running locally.
- `.env` at repo root sets `SPRING_PROFILES_ACTIVE=local`, but it is **not passed into the Docker container**; the effective profile comes from `docker/file-service.env`.

## Architecture notes

- Entry point: `com.demos.file_service.FileServiceApplication` (also set as `start-class` in `pom.xml`).
- HTTP surface: `AssetsController` under `BASE_URI = /api/mgmt/1/assets`.
- Layering: `application/http` → `domain/service` → `domain/repository` → `infrastructure/orm` and `infrastructure/storage/azure`.
- MapStruct: `AssetMapper` is an interface; its implementation is generated by the annotation processor into `target/generated-sources/annotations`. The processor order in `pom.xml` is Lombok → MapStruct → Lombok-MapStruct binding.
- Liquibase master changelog: `src/main/resources/db/changelog/db.changelog-master.yaml`.
- Virtual threads are enabled (`spring.threads.virtual.enabled=true`).

## Spring Boot 4 / dependency quirks

- Do not use `spring-boot-starter-aop`; use `spring-boot-starter-aspectj`.
- Do not use raw `liquibase-core`; use `spring-boot-starter-liquibase`.
- Azure Blob Storage starter is `spring-cloud-azure-starter-storage-blob` (managed by `spring-cloud-azure-dependencies` 7.4.0).
- Resilience4j uses `resilience4j-spring-boot4` plus `resilience4j-reactor`.
- WebFlux test annotations moved packages:
  - `@WebFluxTest` → `org.springframework.boot.webflux.test.autoconfigure.WebFluxTest`
  - `@AutoConfigureWebTestClient` → `org.springframework.boot.webtestclient.autoconfigure.AutoConfigureWebTestClient`
  - Tests already use Spring Framework's `@MockitoBean`; do not revert to the removed `@MockBean`.
- `Dockerfile` uses `eclipse-temurin:25` images, matching the project's Java 25 target.

## VS Code / generated-code guard

- `.vscode/settings.json` disables `java.autobuild.enabled` and excludes `target/` from watchers. This prevents the Eclipse JDT Language Server from overwriting MapStruct-generated classes while editing.

## CI

- `.github/workflows/push_pr.yml`: `mvn clean verify` on PRs.
- `.github/workflows/push_main.yml`: `mvn clean verify`, then `mvn clean install -DskipTests`, then upload `target/app.jar` artifact (retention 2 days).
- Both use Temurin JDK 25 with the Maven cache.
